# P0 화면 명세와 구현 시 확인 사항

2026-10-06 저장한 SVG·MCP·브라우저 주석 기준이다. 화면별 모든 문구·치수는 [노드 목록](node-catalog.md)과 [탐색기](index.html)에 연결했다. 아래 내용은 흐름과 제약을 묶어 읽기 위한 설명이며, 백엔드가 이미 동작한다는 판정이 아니다.

## 공통 레이아웃과 동작

근거: [공통 개발 전달 사항 원문](text/common-guidance.md), 노드 `894:19718`.

- P0는 데스크톱 고정형이다. 별도 모바일 재배치는 범위 밖이다.
- 뷰포트 너비 1440px 미만에서는 사이드바만 아이콘형으로 자동 축소하고 사용자가 토글로 다시 펼칠 수 있다. 본문·표를 임의 줄바꿈하거나 글자를 축소하지 않고 필요한 영역에 가로 스크롤을 둔다.
- 주요 작업·계정 화면은 1920 × 900px로 설계되어 있다. 이는 Figma 프레임 크기이며 브라우저를 강제로 해당 크기로 제한하는 규칙은 아니다.
- 목록 최초 로딩은 구조를 유지한 skeleton이며 애니메이션을 재생한다. 조회 실패를 빈 목록으로 치환하지 않는다.
- 필수 입력과 파일 서버 수신 확인이 끝나기 전 다음/최종 접수 버튼을 비활성화한다.
- 권한 없는 메뉴·탭·버튼은 기본적으로 숨긴다. 프론트 숨김은 서버 권한 검증을 대체하지 않는다.
- 고객지원 버튼의 확인된 주석은 이메일 이동이다. 실제 연락처는 운영 계약을 사용한다. SVG의 `example.com/support`는 예시 링크다.

## 로그인·최초 설정·OTP

섹션 `717:9358`: [화면 문구](text/authentication.md), [SVG](<exports/p0/로그인·최초 설정·OTP/login-my-account-screen.svg>).

1. 발급받은 이메일·비밀번호로 로그인한다. 로그인, 최초 계정 설정 안내, 비밀번호 재설정, 로그인 문제 문의를 구분한다.
2. 최초 설정은 계정 정보 확인 → 비밀번호 → 인증 앱 등록 → 6자리 코드 확인 → 복구 코드 저장 → 완료로 구성된다. 완료 화면은 자동 로그인하지 않고 로그인 이동을 안내한다.
3. 설정 링크 만료/유효하지 않음, 이미 사용됨, 비밀번호 저장 후 OTP 미완료를 각각 다른 상태로 표시한다.
4. 인증 앱 등록은 QR와 수동 등록키를 제공한다. 복구 코드 화면에는 복사·파일 저장·보관 확인 체크가 있다. 샘플 키/코드를 실제 기본값으로 사용하지 않는다.
5. 복구 코드는 일회용이다. 코드 확인 뒤 인증 앱 재등록을 요구하며 MFA 정책을 해제하지 않는다. 앱과 복구 코드를 모두 잃은 경우 운영 본인 확인으로 연결한다. 문의만으로 로그인을 허용하지 않는다.
6. 설정 안내 재요청 결과는 계정 존재를 단정하지 않는 문구를 사용한다. 로그인 인증 실패, OTP 오류, 접근 제한, 비밀번호 불일치, 세션 만료 상태를 별도로 제공한다.
7. 세션 만료는 기존 접수 RPA와 결과 수집의 취소를 뜻하지 않는다. 재로그인 뒤 기존 접수 여부와 최신 상태를 확인한다.

비밀번호 재설정은 운영 본인 확인·승인 후 일회성 링크를 발송하는 흐름이다. 비밀번호 변경/재설정 뒤 기존 세션 종료 안내가 있다. 정확한 endpoint·비밀번호 정책은 API 대응표의 추가 계약 확인 대상이다.
