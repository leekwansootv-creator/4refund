# 간단 견적 기준액 벤치마크

## 문서 목적

이 문서는 간단 견적 산출에 참고한 외부 계산기의 관측값과 4refund 전용 기준액·난수 정책을 기록한다. 외부 사이트를 런타임에 호출하거나 화면·문구·업종 분류를 복제하지 않고, 날짜가 붙은 내부 benchmark snapshot으로만 사용한다.

## 참고 출처와 확인일

| 항목                   | 값                                                                   |
| ---------------------- | -------------------------------------------------------------------- |
| 참고 페이지            | [인크루트 예상 환급액 계산기](https://recruiter.incruit.com/refund/) |
| 확인일                 | 2026-08-05                                                           |
| 내부 benchmark version | `incruit-2026-08-05`                                                 |
| 확인 방식              | 공개 계산기의 업종 코드와 직원 수 1명·10명·100명·1,000명 결과 비교   |

확인 당시 공개 페이지에는 14개 업종과 직원 수 입력이 있었고, IT/정보통신 10명은 화면과 계산 요청 모두 `1,180,000원`을 반환했다. 같은 조건을 8회 반복해도 값이 바뀌지 않아 참고 계산기 자체에는 요청별 난수가 포함되지 않은 것으로 관측했다.

직원 수별 결과를 비교하면 다음 계산과 일치한다.

```text
참고 표시금액 = 업종별 1인당 기준액 × 직원 수
              -> 10,000원 단위 반올림
```

이 계산식은 공개 동작을 표본으로 역산한 내부 추정이다. 인크루트가 공식적으로 제공한 산식이나 환급 보장액으로 해석하지 않는다.

## 4refund 전용 업종과 기준액

참고 업종명과 코드를 그대로 사용하지 않는다. 사용자에게 보여 줄 분류를 4refund 용어로 다시 정의하고 내부 코드도 별도로 관리한다.

4refund 1인당 기준액은 관측 기준액에 5%를 더한 뒤 1,000원 단위로 올림한다.

```text
4refund 1인당 기준액 = ceil(참고 1인당 기준액 × 1.05 / 1,000) × 1,000
```

## 난수와 상향 정책

### 계산식

사용자가 계산 버튼을 실행할 때 1.00%부터 3.00% 사이의 양의 난수를 1bp 단위로 한 번 생성한다.

```text
varianceBps = randomInteger(100, 300)

참고 표시금액 = roundNearest10k(참고 기준액 × 직원 수)

후보 금액 = roundUp10k(
  4refund 기준액 × 직원 수 × (1 + varianceBps / 10,000)
)

최종 예상금액 = max(
  후보 금액,
  참고 표시금액 + 10,000원
)
```

이 방식의 총 상향 폭은 기준액 5%와 양의 난수 1%부터 3%를 합친 수준이다. 최종 1만 원 올림과 최소 차액 규칙 때문에 실제 표시 비율은 입력 금액이 작을수록 더 커질 수 있다.

### 난수 생명주기

- 계산 버튼을 실행할 때 cryptographically secure random source로 `varianceBps`를 생성한다.
- 한 번 표시한 결과는 입력 변경 또는 명시적인 다시 계산 전까지 바꾸지 않는다.
- 상담 제출과 네트워크 재시도에서는 같은 금액과 `varianceBps`를 유지한다.
- Google Sheets에 최종 예상금액, `varianceBps`, 규칙 버전, benchmark version을 함께 저장한다.
- 페이지 렌더, animation, 시간 경과만으로 금액을 다시 뽑지 않는다.

## 벤치마크 갱신 정책

- 외부 계산기를 런타임 dependency로 사용하지 않는다.
- 구현 착수 직전과 예상 견적 규칙을 변경할 때 참고 페이지를 다시 확인한다.
- 외부 값이 바뀌면 새 benchmark version을 만들고 기존 snapshot을 덮어쓰지 않는다.
- 현재 설계의 “항상 더 높음” 보장은 `incruit-2026-08-05` snapshot에 대해서만 성립한다.
- 외부 계산기의 새 값보다 계속 높아야 한다면 공개 전 benchmark refresh를 필수 배포 절차로 둔다.
- 외부 사이트의 화면, 문구, CSS, 이미지, JavaScript를 복사하지 않는다.

## 사용자 안내 원칙

- 결과는 `예상 환급액` 또는 `간단 시뮬레이션 결과`로 표시한다.
- 실제 급여·보험료·신고 자료를 분석한 결과처럼 표현하지 않는다.
- 결과와 가까운 곳에 `업종과 직원 수만으로 계산한 참고용 예상값`임을 알린다.
- 실제 환급 가능 여부와 금액은 상담과 자료 검토 후 달라질 수 있음을 명시한다.
- benchmark 출처와 상향·난수 계산은 내부 정책이며 사용자에게 경쟁사 비교 우위처럼 광고하지 않는다.
