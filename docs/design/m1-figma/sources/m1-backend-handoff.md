# M1 백엔드 인계 · 2026-10-03

M1 백엔드는 PR22로 통합됐고 현재 main에도 포함돼 있다. 다음 작업은 증거와 프론트 연동 인계의 마무리다. 실제 장비·메일·화면·운영 배포를 포함하는 전체 M1 릴리스는 아직 완료로 판정할 수 없다. [로드맵][roadmap]은 이 둘을 명시적으로 구분한다.

검토 기준은 main `ee2fcbaea14026fec46ba9b1ab785844b1fa627c`다. 원격 main과 로컬 기준점 일치를 확인했다. [PR22][pr22]는 2026-09-22 05:26:01 UTC에 `387897b6cf170cacfd9179128d5b2415541930f5`로 병합됐으며 현재 main의 조상이다. 최신 지시에 따라 post-M1 추가 개발과 PR118·119·122의 머지 추진은 보류한다.

## 검증 근거와 제한

- PR22의 통합 시점 기록: system 45, 운영 통합 43, Agent 관련 83, RPA 매핑 131, 문서 13개 통과. 실제 PostgreSQL·loopback HTTPS·별도 합성 프로세스의 증거이며 실제 RPA/두 PC/메일/배포의 증거가 아니다.
- 기존 후속 기록: 현재 기준 main의 RPA adapter 502개 통과 및 공식 fixture 101개 byte-identical. backend/Agent 시험은 여러 SHA·환경·실행 묶음으로 나뉜다. 단일 현재 main의 전체 통과로 합산하지 않는다.
- 현재 main의 별도 승인 130개 선별 시험은 **56 통과·2 실패·72 미실행**이었다. 두 실패는 직접 purged 상태를 만드는 오래된 fixture와 D18 전용 owner의 간접 SELECT 누락이다. 수정 후보 [PR122][pr122]에서 나머지 74개가 통과했지만 **main에는 미병합**이다. 특히 D18은 M1 이력 파기와 관계가 있으므로 운영 권한/실행 환경 검증 시 남은 항목으로 추적한다. 운영 ACL 문제로 단정하거나 권한을 자동 변경하지 않는다.
- PR122의 system 18·Agent 36 통과는 후보 SHA의 증거로 유지한다. 과거의 Windows 접근 실패를 제품 실패 또는 현재 main 검증 완료로 바꾸지 않는다. Linux 전용 14개 미실행도 보존하되 post-M1 시험까지 M1 필수로 일괄 편입하지 않는다.
- 이번 최소 검증: 현재 main에 M1 병합 커밋이 포함돼 있고 작업 트리가 깨끗함을 확인했다. 인수 원장 24개 사례의 시험 함수 참조 45개가 모두 존재한다. 이는 정적 확인이며 실행 가능성·사업 규칙 통과를 증명하지 않는다.
- 오래된 원장의 `pending` 표시는 후속 통합 근거와 함께 읽는다. 해당 문자열만으로 구현 누락을 확정하지 않는다. 이번에는 기존 성공 시험, Actions, 자동 리뷰를 재실행하지 않았다.

## 남은 순서와 안전 경계

1. 10월 5일 월요일 프론트 설계는 사용자가 별도 담당자와 진행한다. 우리는 기존 M1 API 계약과 미결 연동사항만 전달하며 화면 기획·디자인을 시작하지 않는다. 현재 문서의 SMS·자료 인수 확인·일괄 발급을 필수 화면으로 확대하지 않는다.
2. 실제 연동 전에 사용할 **배포 후보 SHA와 조립된 인증/파일/접수/메일 포트**를 고정한다. 현재 main에 후속 코드가 섞여 있으므로 ‘M1까지만’이 자동 rollback이나 안전한 기능 차단을 뜻하지 않는다. 미조립 포트는 `POLICY_NOT_CONFIGURED`로 닫히는 코드가 있으며, 실제 설정은 이번에 조회·변경하지 않았다. [앱 조립][registry]·[인증 설정][identity-config]
3. 그 후보가 정해진 뒤 필요한 최소 검증만 선정한다. D18의 운영 이력 파기 권한과 해당 후보에서 달라진 필수 흐름이 우선이다. 이미 확보한 시험 증거를 재사용하며, 필요한 추가 수정의 영향과 범위는 별도로 정한다. PR122는 미병합 상태로 유지한다.
4. E-01: 허용 샘플·두 기능 실행물/설정/산출물·공유 세션 제약을 받고 실제 RPA 담당자와 인수한다. E-02: 두 PC/WSL/저장소/백업·복원·SSH·운영 배포 환경과 담당을 확인한다. E-03: 실제 메일 발송/복구·지원 처리 경로를 확인한다. 연락·발송·실행은 별도 승인된 범위에서만 한다.
5. 전체 M1 종료는 최소 화면과 실인수 후, 실제 계정의 로그인→접수→결과→신고 배정 및 배포 기록을 확보했을 때 판정한다. 현재 인계문서 완성으로 출시를 닫지 않는다.

M1에서 제외할 후속 범위: CR-002 자료 인수 기반 새 기한·기존 자료 전환·추가 백업 정책, CR-004 SMS, CR-003 일괄 계정 발급, P1 취소·고급 검색·알림·문의함, P2 운영 대시보드 및 정산 후보. 기존 M1의 보관·복원·최소 운영 의무까지 제외하는 것은 아니다.
