# 4refund 랜딩페이지 오프라인 디자인 자료

2026-10-27에 확인한 랜딩페이지 변경안을 Figma 연결 없이 구현·검수하기 위한 자료다. 화면 캡처뿐 아니라 실제 이미지·SVG 에셋과 문구·치수·이미지 크롭·모션을 함께 보존했다. 앱 기능이나 Figma 디자인을 변경한 결과물이 아니다.

## 읽는 순서

1. [변경 기획과 뉴스 관리 요구사항](../../planning/landing-page-2026-10-change-plan.md)
2. [오프라인 구현 명세](IMPLEMENTATION-SPEC.md)
3. [전체와 섹션별 화면 모음](index.html)
4. [전체 문구 색인](CONTENT.md)과 [이미지 에셋 목록](ASSETS.md)
5. 필요한 노드의 상세값을 `reference`에서 검색

`index.html`은 파일을 직접 열어 볼 수 있는 정적 참고 문서다. 스크립트·외부 CDN·원격 폰트·Figma 세션·API 키를 사용하지 않는다. PNG와 SVG도 모두 이 폴더 안에 있다. 개발 서버를 실행하지 않고 화면을 확인할 수 있다.

## 기준과 우선순위

- 저장소 기준: `main`, `ac39eda43b519681262919caae822e4d65d8cea0`.
- Figma 파일 식별자: `ijPZL5WxrjvxbHjBp0DoQa`.
- 주 기준: `2163:4123`, 랜딩페이지_2026-10 변경안, 1920 × 8324.28px.
- 보조 비교: 인접한 `404:2434`. 기존 문서의 `290:387`·`27:373`과 같은 이력이라고 보증하지 않는다.
- 별도 팝업: `2179:30520`, 용도 미정. 과거 입력 팝업 `324:500`은 충돌 확인용이며 현재 제품 흐름으로 적용하지 않는다.

적용 우선순위는 **사용자가 확정한 제품 정책과 변경 기획 → 오프라인 구현 명세 → 보존 화면·상세 노드 자료**다. 원문에 남은 오타·연락처 불일치·과거 개인정보 선입력 연결을 그대로 복원하지 않는다. 미결정 사항은 변경 기획의 D01부터 D13까지를 따른다.

Figma에서 보이는 문구가 실제 운영 사실을 입증하는 것은 아니다. 특허·국내 최초·제품 적용·인물 경력·연락처는 기획에 명시한 확정 절차를 거친다. 누락된 모바일·관리자 화면을 존재하는 시안처럼 해석하지 않는다.

## 애플리케이션 빌드와의 분리

이 폴더의 `.gitignore`는 보존 자료를 Tailwind의 자동 클래스 검색에서 제외한다. [Tailwind의 파일 검색 규칙](https://tailwindcss.com/docs/detecting-classes-in-source-files#which-files-are-scanned)에 따라 원문 JSX·JSON·HTML의 예시 클래스가 홈페이지 CSS로 생성되는 것을 막는다. 자료는 Git에 명시적으로 추적하며, 이 규칙이 커밋된 파일을 삭제하거나 제외하는 것은 아니다.

기존 추적 파일은 일반적으로 수정·스테이징할 수 있다. 새 자료를 추가할 때는 대상 파일을 확인한 뒤 `git add -f -- <파일 경로>`로 명시적으로 추가하고 `manifest.json`을 갱신한다. 포맷 검사는 `npx prettier --check --ignore-path .prettierignore docs/design/landing-page-2026-10`으로 실행한다. 애플리케이션 소스·스타일·빌드 설정은 변경하지 않는다.

## 상세값을 찾는 방법

예를 들어 부센터장 사진은 `2179:30868`, AI 이미지는 `2163:4292`, 뉴스 영역은 `2163:4347`이다. `nodes.json`에서 노드 ID를 찾고 `image-slots.json`에서 해당 부모 노드를 찾으면 원본 이미지와 표시 영역·크롭을 함께 확인할 수 있다. 새 에셋의 의미와 주요 사용 위치는 구현 명세에도 정리되어 있다.

`reference`의 JSX·Tailwind·motion 표현은 Figma가 생성한 디자인 자료이며 실행 가능한 애플리케이션 코드가 아니다. 그대로 복사하거나 `motion/react` 의존성을 추가하지 않는다. 기존 컴포넌트·CSS·접근성·상태 관리에 맞게 옮긴다. `w-[282px]`, `text-[64px]`, `leading-[1.6]` 등은 각각 폭·글자 크기·줄 높이의 원문 수치다. 별도 node ID가 없는 자식의 크롭·회전은 `image-slots.json`과 원문 계층을 같이 본다.

에셋 47개 중 14개는 기준 커밋의 `public` 파일과 SHA-256이 같다. 같은 바이트가 확인된 파일은 `assets.json`의 `existingMatches`를 근거로 기존 경로를 재사용할 수 있다. 나머지 에셋을 모두 새 디자인 요소라고 추정하지 않는다. 기존 이미지의 다른 export나 보조 비교 프레임용 이미지도 포함된다.

에셋 파일명은 Figma가 제공한 이름을 보존했다. 뉴스 예시 이미지 `7a6ae40e5bf22b851c649cdd961d6f9bd177aed6.png`는 확장자와 달리 실제 JPEG이며 1584 × 672px다. `assets.json`의 `format`·`mimeType`은 원본 메타데이터로 확인한 값이다. 실제 구현 경로로 옮길 때는 올바른 확장자와 MIME을 사용하고, 보존 원본은 덮어쓰지 않는다.

## 화면 캡처의 한계

Figma 도구는 긴 프레임을 축소한다. 전체 캡처는 237 × 1024px, 주요 섹션 캡처는 대체로 폭 1024px다. 전체 이미지를 확대해 간격이나 글꼴 크기를 측정하지 않는다. CSS 기준 치수는 구현 명세와 `section-metadata.json`을 사용하며, 원본 PNG·SVG의 해상도는 `assets.json`에 있다. 인물과 뉴스 카드에는 별도 확대 캡처가 있다.

캡처는 정적 상태다. 전체 이미지를 홈페이지 배경으로 사용하는 구현은 허용하지 않는다. 이미지 부품은 `assets`를 사용하고 문구·링크·버튼은 실제 요소로 구현한다.

## Figma 없이 가능한 작업과 남은 결정

- 데스크톱의 센터·전문가·뉴스·Footer 구조, 문구 후보, 이미지와 크롭을 확인할 수 있다.
- 기존 조회 계약을 보존하면서 디자인을 반영하고 로컬 캡처와 시각 비교할 수 있다.
- 뉴스 URL 등록·게시 기능의 범위와 정적 호스팅 제약은 변경 기획만으로 검토할 수 있다.
- 모바일의 신규 배치, 뉴스 관리 화면, 별도 팝업 용도·동작은 확정 시안이 없다. 기존 반응형과 이 문서의 제안을 토대로 사용자와 결정한다. 이 결정을 위해 Figma 재연결을 필수로 요구하지 않는다.
- 후속 구현은 이 스냅샷을 사용한다. 새로운 디자인 변경 요청이 없는 한 Figma 도구의 접속 성공을 작업 시작 조건으로 삼지 않는다.
