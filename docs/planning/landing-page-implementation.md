# 랜딩 페이지 구현 기획

## 문서 목적

이 문서는 Figma의 랜딩 페이지를 Next.js 애플리케이션으로 구현하기 위한 단일 기준이다. 개발자는 이 문서에서 화면 구조, 콘텐츠, 컴포넌트 소유권, 상호작용, 반응형, 에셋, 모션, 접근성, 검수 범위를 확인하고 구현한다.

이 문서가 대상으로 하는 화면은 루트 경로 `/`의 단일 랜딩 페이지다. 문의 폼, 서버 제출, 데이터베이스, 관리자 기능은 포함하지 않는다.

간단 견적과 개인정보 제출은 현재 랜딩 구현 범위에 포함하지 않는다. 디자인 전 기술 작업과 디자인 후 화면 작업은 위 후속 PR 로드맵에 따라 별도 feature에서 진행하며, 최종 공개 PR 전까지 현재 랜딩에 진입점을 연결하지 않는다.

## 가장 중요한 구현 원칙

Figma의 [컴포넌트 모음 `37:512`](https://www.figma.com/design/ijPZL5WxrjvxbHjBp0DoQa/4%EB%8C%80%EB%B3%B4%ED%97%98-%ED%99%98%EA%B8%89%EC%84%BC%ED%84%B0?node-id=37-512&m=dev)은 코드의 공통 컴포넌트 목록이 아니다.

- 컴포넌트 모음은 hover, active 상태와 디자인 치수를 확인하는 참고자료로만 사용한다.
- Figma에서 component 또는 instance인지는 코드 공통화의 근거가 아니다.
- 첫 구현의 모든 화면 조각은 `landing-page` feature가 소유한다.
- 같은 모양이 반복되어도 의미, 동작, 접근성, 변경 이유가 다르면 분리한다.
- `shared/components`에는 컴포넌트를 선제적으로 추가하지 않는다.
- 둘 이상의 실제 feature가 같은 의미와 동작으로 사용하게 된 뒤에만 `docs/engineering/code-conventions.md`의 기준으로 승격을 검토한다.

## 사용자 흐름과 공개 인터페이스

### 라우트

```text
GET /
```

`src/app/page.tsx`는 별도 데이터 처리 없이 `LandingPage`를 조합하는 얇은 진입점이다.

```tsx
import { LandingPage } from "@/features/landing-page";

export default function HomePage() {
  return <LandingPage />;
}
```

실제 구현에서는 프로젝트 주석 규칙에 따라 내보내는 함수에 TSDoc을 작성한다.

### 앵커 계약

| 앵커         | 연결 메뉴 또는 CTA | 대상 섹션                    |
| ------------ | ------------------ | ---------------------------- |
| `#top`       | 로고               | 페이지 시작                  |
| `#about`     | 센터 소개          | 센터 소개                    |
| `#services`  | 주요 서비스        | 서비스·혜택과 환급 사례 시작 |
| `#strengths` | 전문가 강점        | 전문가 강점 소개             |
| `#process`   | 환급 절차          | 4단계 환급 절차              |
| `#contact`   | 무료 진단 신청     | 하단 문의 CTA                |

섹션 heading 또는 section root에 안정적인 `id`를 부여한다. 동일 페이지 링크는 JavaScript 라우팅으로 바꾸지 않고 네이티브 앵커를 사용한다.

| 용도           | 표시값               | 링크                        |

## 반응형 전략

모바일 Figma가 없으므로 새로운 정보 구조나 기능을 발명하지 않는다. 데스크톱 콘텐츠의 의미와 순서를 유지하면서 줄바꿈, 수직 적층, touch 조작, 가로 넘침을 해결한다.

| viewport    | 레이아웃 원칙                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 1280px 이상 | Figma의 1280px 컨테이너와 45px 내부 여백을 유지하고 1920px에서 시각 일치 검수                                                           |

## 상태와 접근성

### 의미 요소

- `header`, `nav`, `main`, `section`, `footer`, `address`를 용도에 맞게 사용한다.
- 페이지의 `h1`은 히어로 제목 하나만 사용한다.
- 각 주요 section은 `h2`, 내부 항목은 `h3`으로 계층을 유지한다.
- 링크 동작은 `<a>`, 혜택 상태 변경은 `<button>`을 사용한다.
- 클릭 가능한 `<div>`를 만들지 않는다.

### keyboard와 focus

- 모든 메뉴, CTA, 혜택 버튼에 명확한 `focus-visible` outline을 제공한다.
- hover에서 확인 가능한 내용은 focus 또는 click으로도 동일하게 확인할 수 있어야 한다.
- 자동 이동 중인 환급 사례 내부에 focus가 들어오면 이동을 정지한다.
- DOM 순서와 데스크톱 CSS 배치 순서를 다르게 만들더라도 keyboard 순서는 의미 흐름을 따른다.

### 이미지

- 사람을 식별하는 센터장 사진만 정보 이미지로 취급한다.
- 텍스트 의미를 반복하는 3D 아이콘, section 배경, 사례 배경, 연락 아이콘은 장식 처리한다.
- 장식 SVG는 `aria-hidden="true"`와 focus 제외를 적용한다.

## 모션 구현

모션은 정적 레이아웃, 반응형, 기본 연락 동작이 완료된 다음 단계에서 구현한다. Figma가 생성한 `motion/react` 코드는 참고자료이며 해당 패키지를 추가하지 않는다.

### 공통 주기

```css
--landing-motion-duration: 28.020507s;
```

### 확인된 모션

| 대상               | Figma 노드                                 | 동작                                                 |
| ------------------ | ------------------------------------------ | ---------------------------------------------------- |
| 혜택 section       | `38:1054`                                  | opacity 0→1, y 200→0, 전체 주기의 첫 2.5%에 ease-out |
| 환급 사례 track    | `130:540`                                  | x 0→-2679px, 28.020507초 linear infinite             |
| 전문가 도입 텍스트 | `41:1880`                                  | opacity 0→1, x -200→0                                |
| 전문가 도입 이미지 | `60:2975`                                  | opacity 0→1, x 200→0                                 |
| 세 강점 이미지     | `60:2730`, `60:3225`, `60:3475`            | y 0↔-20px 강조 후 나머지 주기 유지                   |
| 세 강점 텍스트     | `41:2038`, `42:2058`, `42:2067`            | 좌우 방향에서 opacity/translate reveal               |
| 환급 절차 카드     | `41:1789`, `41:1797`, `41:1805`, `41:1813` | 순차적으로 scale 1→1.08→1 pulse                      |

동일한 모션은 CSS keyframes와 animation utility를 공유한다. 동일 keyframes를 사용한다는 이유로 `ExpertStrengthCard`, `ProcessCard`처럼 의미가 다른 컴포넌트를 하나로 합치지 않는다.

혜택 section, 전문가 도입 텍스트·이미지, 세 강점 텍스트의 진입 모션은 각 대상이 viewport에 25% 노출되고 아래 방향으로 스크롤할 때 페이지 로드당 한 번만 재생한다. 위 방향 스크롤에서는 시작하지 않고, 이미 재생한 대상은 최종 상태를 유지한다. 환급 사례 track, 세 강점 이미지, 환급 절차 카드의 반복 모션은 기존 28.020507초 CSS 타임라인을 유지한다.

### reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  /* 모든 자동 반복을 중지하고 opacity: 1, transform: none인 최종 상태를 표시한다. */
}
```

- 환급 사례는 정적 가로 목록으로 남긴다.
- reveal 대상은 최종 위치와 완전한 opacity로 표시한다.
- 절차 카드는 확대하지 않는다.
- 콘텐츠가 motion에 의존해 나타나거나 사라지면 안 된다.

### 4단계: 모션과 최종 시각 검수

- 공통 28.020507초 CSS 타임라인을 구현한다.
- 사례 이동, 강점 이미지, 절차 pulse를 Figma 모션 데이터와 비교한다.
- 혜택·전문가 텍스트 reveal은 아래 방향 25% 진입 시 페이지당 한 번만 재생한다.
- reduced motion과 hover/focus pause를 적용한다.

완료 조건:

- 새 모션 라이브러리 의존성이 없다.
- reduced motion에서 모든 콘텐츠가 최종 정적 상태로 보인다.
- 모션 중에도 keyboard 조작과 읽기가 방해받지 않는다.

## 검수 계획

### 시각 검수

- 1920px 전체 페이지를 Figma `27:373` screenshot과 비교한다.
- 헤더, 히어로, 센터 소개, 혜택, 사례, 강점, 절차, CTA, 푸터를 개별 node screenshot과 비교한다.
- 색상, 폰트, 여백, radius, 이미지 crop, overlay, 정렬 차이를 section별로 기록한다.
- 전체 화면 축소 screenshot만 보고 완료하지 않는다. 텍스트와 아이콘은 section screenshot으로 확인한다.

### viewport 검수

| viewport | 확인 항목                                                                           |
| -------- | ----------------------------------------------------------------------------------- |
| 1920px   | Figma 1:1 기준, 1280px 컨테이너 위치, section 높이와 정렬                           |
| 1280px   | 컨테이너 수축, 45px 이하 안전 여백, heading과 카드 겹침 없음                        |
| 768px    | grid 전환, 2단 compact 헤더와 네 메뉴 한 줄 배치, 이미지·텍스트 읽기 순서           |
| 375px    | 긴 한국어, 전화, 이메일, 주소, 사업자 정보, CTA touch 영역, 페이지 가로 스크롤 없음 |

### 기능 검수

- 로고가 `#top`으로 이동한다.
- 네 개 메뉴가 정의된 section anchor로 이동한다.
- 무료 진단 신청이 `#contact`로 이동한다.
- 헤더·히어로·CTA의 상담 전화 링크가 `tel:01022250555`다.
- 푸터의 회사 대표전화 링크가 `tel:0234635119`이고 팩스가 `02-3462-5119`로 표시된다.
- 모든 이메일 링크가 `mailto:iwillceo@naver.com`이다.
- 혜택 항목을 mouse, keyboard, touch로 선택할 수 있다.
- 환급 사례 자동 이동은 hover, focus, reduced motion에서 정지한다.

### 접근성 검수

- 페이지에 `h1`이 하나 존재하고 heading 순서가 건너뛰지 않는다.
- landmark가 중복되거나 잘못 중첩되지 않는다.
- 모든 interactive element에 접근 가능한 이름과 focus 표시가 있다.
- 장식 이미지와 정보 이미지를 구분한다.
- 200% 확대에서도 콘텐츠와 동작이 손실되지 않는다.
- `prefers-reduced-motion: reduce`에서 자동 반복이 없다.
