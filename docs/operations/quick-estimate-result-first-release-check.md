### 발견사항과 수정

- 초기 업종 안내와 입력 placeholder의 명암 대비가 2.09:1로 axe 기준을 충족하지 못했다. 글자색을 `#666`으로 조정했다.
- 빈 연락처에서 동의 전문으로 이동할 때 blur 오류가 후속 버튼을 밀어 첫 클릭이 누락됐다. 연락처 필드에 오류 안내 공간을 예약하고 첫 클릭으로 전문이 열리는 브라우저 회귀 검증을 추가했다.
- CSS `zoom: 2`는 `vh` 영역을 줄이지 않아 브라우저 확대와 다른 clipping을 만들었다. 확대 대응 검사는 가용 CSS viewport를 절반으로 줄이는 방식으로 정정했다. native dialog의 브라우저 주소창 이동과 배경 UI 포커스 이탈도 구분한다.

## 실제 저장 대조 절차

1. 문서의 승인 운영 계정에서 테스트용 Web App과 대응 Sheet를 식별하고 쓰기·조회·알림 확인 범위를 확인한다. 실제 고객 데이터와 분리된 테스트 환경을 우선한다.
2. 저장소 밖 환경 설정으로 endpoint를 주입한다. 다음은 반복 검증 절차다. 이번에 실제 실행한 범위와 결과는 아래 별도 기록을 따른다.

```powershell

```

3. 가짜 회사명은 삭제대상 표식, 이메일은 `.test` 도메인을 사용한다. 실제 연락처는 입력하지 않는다.

## 접근 기준 승인과 최종 공개 조건

RF-PR4에서 실제 Sheet의 일반 액세스 `제한됨`과 소유자 외 기존 편집자 3명을 확인해 당시 소유자만 접근하도록 정한 문서와의 차이를 보고했다. 기존 3명의 상담 원본 포함 Sheet 접근 유지·문서 갱신·최종 배포를 질문한 뒤, 사용자가 검증 후 main 출하를 지시했다. 이 승인을 [운영 runbook](quick-estimate-runbook.md#2026-09-04-접근-기준-승인)과 관련 기획 문서에 반영해 해당 공개 차단을 해소한다.

실제 공유 설정·기존 편집자 권한은 변경하지 않는다. 승인은 확인된 기존 3명에 한하며 추가 초대·권한 확대·자동 배정 변경은 포함하지 않는다. 제품 런타임과 제출 계약이 실제 저장 검증 당시와 동일하므로 문서 정정만을 위한 새 테스트 접수는 만들지 않는다. RF-PR5는 최신 누적 diff 검수, 전체 검사, 리뷰·필수 검사 상태 확인 후 main에 병합하고 해당 merge commit의 배포 성공과 공개 선조회 동작을 확인한다.

## 운영 전달 사항과 롤백

- 상담 목록과 신규 알림에는 **상세 견적 신청자만** 남는다. 계산만 한 사용자는 저장하지 않으며 신청 건수를 전체 조회 건수로 해석할 수 없다.
- 상세 견적은 상담을 통한 안내다. 회사 정보 입력 후 정밀 금액이 자동 산출되는 기능이 아니다.
- 계산·고지·payload·시트 schema와 Apps Script artifact 변경 없음. 이 프런트엔드 전환만을 위한 Apps Script 재배포나 DB migration은 없다.
- 공개 후 문제는 릴리스 변경을 revert하고 GitHub Pages 배포를 확인한다. 기존 상담 행은 변경하지 않는다. 롤백 시 연락처 우선·조회 동시 접수로 돌아가는 의미를 운영 담당자에게 알린다.
- main 병합 전 실제 저장·미해결 리뷰·필수 검사·테스트 정리 조건을 확인하고, 병합 후에는 해당 merge commit의 `verify`와 `deploy-pages` 성공 및 공개 화면 선조회를 확인한다. 공개 화면 확인을 위해 새 상담 신청을 만들지 않는다.
