# 신규 계정 접수 환경 준비 기록

최초 생성 시점의 기록은 아래에 보존한다. 같은 날 이어진 보호·검증·서식 준비는 마지막의 **빈 신규 시트 준비 도구와 후속 검증** 절에서 확인한다.

## 범위와 상태

2026-10-23에 사용자가 지정한 miningdev8 계정에 별도의 Google Sheets와 Apps Script 프로젝트를 만들었다. 기존 계정의 시트·스크립트·접수 이력·권한과 기존 로컬 변경사항은 보존했다. 기존 데이터 이관, 홈페이지 접수 주소 변경, 실제 접수·알림, Apps Script 함수 실행·트리거 설치·웹앱 배포, GitHub 변경·공개 배포는 수행하지 않았다.

현재 상태는 **새 자산과 코드·빈 스키마를 저장한 준비 단계**다. 운영 초기화·권한 승인·연동 검증이 완료된 환경으로 간주하지 않는다. 출처 schema 표식은 `pending`이다. 이 표식은 v2 저장 준비 조건이며 모든 구형 요청을 차단하는 전역 접수 스위치는 아니다. 현재 접수 경로가 없는 근거는 웹앱 배포가 없고 홈페이지 주소를 연결하지 않았다는 점이다.

[출시·복구 절차](quick-estimate-embed-release.md)의 기존 Google 자원 점검·업데이트 경로에 추가되는 **새 계정의 독립 환경 준비 기록**이다. 이전 문서의 미실행 기록은 그 시점의 기록으로 보존한다. 설치 방식과 제휴사 전달물은 기존 [설치 가이드](../engineering/quick-estimate-embed-installation.md)와 [전달 가이드](../engineering/quick-estimate-embed-partner-handoff.md)를 계속 사용한다.

## 생성한 자산

| 자산          | 이름                                      | 확인한 상태                                                                  |
| ------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| Google Sheets | `4refund 접수 준비 · miningdev8 · 미연결` | 해당 계정의 `내 드라이브/ChatGPT`, 나에게만 공개, 상담 데이터 0건            |
| Apps Script   | `4refund 접수 준비 · miningdev8 · 미배포` | 해당 계정으로 생성·저장, 활성·보관 배포 모두 없음, 트리거 0개, 실행 기록 0개 |

실제 자산 URL과 ID는 작업 결과의 비공개 전달 링크 및 새 프로젝트의 Script properties에서 확인한다. 저장소 문서나 환경 변수에 복사하지 않았다. 새 프로젝트의 공유 대화상자는 조회 중 Google 오류가 발생하여 공유 ACL 상세 재확인은 남아 있다. 공유 대상·소유권·접근 권한은 변경하지 않았다.

연결된 Drive 도구의 계정은 지정 계정과 달라 생성에 사용하지 않았다. miningdev8 Chrome에서 생성했다. 로컬 XLSX를 작성·검증했으나 Chrome의 파일 업로드 권한 오류로 업로드를 완료하지 못했다. 대신 새 Google Sheets 편집 화면에 스키마를 입력한 뒤 고정 값으로 저장하고, 내려받은 실제 시트의 값을 로컬 스키마와 대조했다. 업로드 중간 파일은 운영 자산이 아니다.

## 저장된 시트 구조와 검증

| 탭          | 범위     | 실제 저장 내용                                            |
| ----------- | -------- | --------------------------------------------------------- |
| `상담 목록` | `A1:R1`  | `ATTRIBUTED_CONSULTATION_HEADERS`의 18개 헤더와 순서 일치 |
| `leads`     | `A1:AC1` | `ATTRIBUTED_LEAD_HEADERS`의 29개 헤더와 순서 일치         |
| `codebook`  | `A1:C40` | 기본 코드북과 출처 확장 항목의 40행 일치                  |

새 시트에서 내보낸 XLSX의 모든 값이 있는 행을 검사했다. `leads`와 `상담 목록`은 각각 헤더 1행뿐이고, `codebook`은 40행뿐이다. 세 탭 모두 수식 0개다. 샘플 고객이나 실제 개인정보를 입력하지 않았다.

헤더 구분 색상·굵기·줄바꿈, 세 탭의 첫 행 고정, 상담 목록 `A1:R1000` 필터를 적용했다. 아직 운영 초기화 전체를 수행한 것은 아니다. 다음 항목은 활성화 전 새 시트에 적용하고 readback해야 한다.

- 원본·상담 헤더 및 원본 투영·동의·식별·출처 범위 보호와 허용 편집자
- 상담 신청 번호 P열 숨김, 상담 목록 첫 2열 고정 및 운영 열 너비
- 상태·담당자·상담 결과·다음 연락일 검증과 조건부 서식, 전화번호·숫자·금액 서식
- 스프레드시트 locale·시간대와 운영 보유·파기 절차

`setupQuickEstimateStorage()`는 트리거를 생성하므로 이번 준비 단계에서 실행하지 않았다. 이미 헤더가 있는 시트에서는 최초 생성용 `initializeSpreadsheet()`와 `initializeConsultationSheet()`를 모두 다시 실행하는 함수가 아니다. **후속 작업에서 setup 한 번으로 위 보호·서식이 모두 채워진다고 가정하지 않는다.** 기존 시트를 지우거나 새로 생성하는 대신 새 빈 시트에 필요한 설정만 적용하는 검증된 초기화 작업 또는 명시적 수동 설정을 준비한다.

## 저장한 Apps Script 코드와 설정

`Code.gs`는 현재 로컬 `integrations/google-apps-script/quick-estimate/Code.gs`와 개행 정규화 후 전체 내용이 일치함을 편집기 readback으로 확인했다. 저장한 원본 파일의 SHA-256은 다음과 같다.

```text
11ffadb25a733739f46f1168fa71741bac466b5c91449dc9f45f5ac407b9b293
```

미커밋 로컬 후보를 저장한 것이며 운영 릴리스 승인이나 공개 버전을 뜻하지 않는다. 저장소 코드·생성 artifact는 수정하지 않았다.

새 프로젝트의 `appsscript.json`은 준비 단계에 맞춰 저장소의 운영 manifest보다 권한 선언을 좁혔다.

```json
{
  "timeZone": "Asia/Seoul",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/userinfo.email"
  ],
  "webapp": {
    "access": "MYSELF",
    "executeAs": "USER_DEPLOYING"
  }
}
```

메일 발송 및 설치형 트리거 관리 scope를 선언하지 않았다. OAuth 동의도 수행하지 않았다. `MYSELF`는 저장된 설정값일 뿐, 소유자 전용 웹앱을 배포했다는 뜻이 아니다. 운영 manifest로 전환·재인증·트리거 설치·배포는 별도의 활성화 단계다. 이 준비용 manifest를 기존 운영 프로젝트에 복사하지 않는다.

| Script property                           | 상태                                       |
| ----------------------------------------- | ------------------------------------------ |
| `QUICK_ESTIMATE_SPREADSHEET_ID`           | 이번에 만든 새 시트의 ID만 저장하고 재확인 |
| `QUICK_ESTIMATE_ATTRIBUTION_SCHEMA`       | `pending` 저장 및 재확인                   |
| 알림 수신자·홈페이지 origin·제한 override | 미설정                                     |

현재 기본 상담 담당자 문자열은 코드의 `DEFAULT_CONSULTATION_ASSIGNEE = "이관수"`다. 저장소 소유 계정을 바꿔도 이 업무 담당자는 자동으로 바뀌지 않는다. 사용자 지정 계정 이름을 상담 담당자 이름으로 임의 대입하지 않았다. 실제 운영 시작 전에 담당자 표기와 알림 수신자를 설정해야 한다.

## 후속 준비와 활성화 순서

1. **새 환경 설정 완성:** 신규 자산 ID·소유자·공유 범위를 다시 확인한다. 위 미적용 보호·검증·서식을 새 빈 시트에만 설정하는 절차를 준비한다. 함수 실행이 필요하면 정확한 scope에 대한 계정 소유자의 OAuth 동의를 받은 뒤 실행한다. 메일·트리거 생성 없이 가능한 단계와 활성화 단계를 분리한다.
2. **출처 schema 검증:** 새 시트의 기본 설정 후 `migrateQuickEstimateAttribution()`을 새 프로젝트에서 실행한다. 이 함수는 출처 보호·필터·숨김 열 등의 readback 성공 후에만 표식을 `2`로 바꾼다. 헤더가 있다는 이유로 사람이 `pending`을 `2`로 먼저 바꾸지 않는다.
3. **운영 담당·설정 확정:** 상담 담당자와 알림 수신자, 실제 홈페이지 origin, 개인정보 고지, 제출 제한을 확인한다. 분당 10건·일일 100건·동일 연락처 시간당 3건은 애플리케이션의 보수적인 기본 방어 설정이며 Google의 최대 처리량이 아니다. 설정으로 조정할 수 있으나 실제 처리 여력·quota 확인 없이 새 숫자를 확정하지 않는다.
4. **실행 권한과 접수 환경 활성화:** 승인된 운영 manifest·권한으로 전환하고 필요한 트리거와 웹앱 배포를 구성한다. 준비용 scope로 운영 setup을 실행하지 않는다. 이 단계는 이번 작업 범위 밖이다.
5. **명시적으로 승인한 연동 검증:** 대상 시트·접수 건수·알림 수신자·정리 정책이 정해진 별도 검증에서 저장·원본/상담 동기화·같은 payload 재시도·알림을 확인한다. 일반 자동 테스트 통과를 Google 연동 성공으로 대체하지 않는다.
6. **홈페이지·외부 모듈 전환:** 운영 준비 증거를 확인한 뒤 새 endpoint로 후보를 빌드하고 정해진 출시 절차를 따른다. 이후 실제 URL을 넣은 설치 코드·제휴사 전달 묶음을 제공한다. 제휴처나 캠페인 계약의 미확정 자체가 기술 준비를 중단할 사유는 아니다.

기존 계정 자산은 새 환경의 초기화 대상이나 자동 fallback이 아니다. 과거 신청은 새 환경에 복제하지 않았다. 전환 이후 장애가 생겨도 접근하지 못한 기존 계정의 운영 가능성을 가정하여 URL만 되돌리지 않는다. 확인된 직전 공개본·endpoint·고정 자원과 승인된 복구 절차를 사용한다.

## 이번 검증의 범위

Node.js 22.15.0 / npm 10.9.2 환경에서 `QUICK_ESTIMATE_LIVE_E2E=0`으로 `npm run check`를 수행했다. 포맷·lint·타입·구조·주석·Apps Script artifact 일치, 도구 테스트 21개, Vitest 32개 파일의 247개 테스트, E2E 빌드와 브라우저 테스트 35개가 통과했다. 실제 저장 E2E 5개는 건너뛰었다.

브라우저에서 새 시트의 계정·저장 상태, 값 readback, 새 프로젝트의 코드·속성·배포 없음·트리거 0개·실행 기록 0개를 확인했다. Google 함수 실행·메일 발송·접수 저장 성능·실제 quota는 확인하지 않았다. 새 프로젝트 공유 ACL 상세는 Google 공유 대화상자의 조회 오류로 미확인이다.

## 빈 신규 시트 준비 도구와 후속 검증

사용자가 새 시트의 보호·입력 검증·서식·출처 schema 준비를 추가로 승인했다. 최초 실행 시 Google이 요청한 `spreadsheets`와 `userinfo.email` 두 scope는 실제 승인 화면에서 사용자에게 범위를 설명하고 별도 승인을 받은 뒤 허용했다. Sheets OAuth 권한은 계정의 모든 시트 범위이며 특정 문서로 한정된 권한이 아니다. 코드의 대상 제한과 OAuth 권한 범위를 혼동하지 않는다. 메일·트리거 관리 scope는 추가하지 않았다.

### 준비 코드의 경계와 재현 방법

원본은 `integrations/google-apps-script/quick-estimate/src/empty-storage-preparation.ts`다. 기존 운영 `Code.gs`와 별도로 `Preparation.gs`를 생성하여 **새 미배포 프로젝트에만** 저장한다.

```powershell
node scripts/build-empty-storage-preparation.mjs <별도-출력-폴더>/Preparation.gs
```

빌더는 기존 출력 파일을 덮어쓰지 않는다. 운영 `Code.gs`를 출력 경로로 지정해도 실패한다. 생성물에 접수 진입점, MailApp·GmailApp·ScriptApp·UrlFetchApp 또는 브라우저 runtime이 있으면 실패하며 Google service 없는 VM 초기화도 검사한다. 준비 도구의 회귀 테스트는 `npm run check`에 포함했다.

별도 Script properties `QUICK_ESTIMATE_PREPARATION_TARGET_ID`와 `QUICK_ESTIMATE_PREPARATION_OWNER_EMAIL`을 설정했다. 첫 값은 기존 `QUICK_ESTIMATE_SPREADSHEET_ID`와 같아야 하며, 계정은 실행자와 소유자 모두 일치해야 한다. 자산 ID·계정값은 저장소 소스에 넣지 않는다.

- `prepareEmptyQuickEstimateStorage()`: 정확한 3개 탭, 29/18개 헤더, codebook 40행, 접수 0행, 수식 0개, 인식 가능한 보호·필터를 확인한다. 기본 설정을 적용하고 값 보존을 읽어 확인한 뒤 출처 migration을 실행한다. 검증 실패 시 schema를 `pending`으로 유지한다. `setupQuickEstimateStorage()`는 호출하지 않는다.
- `verifyEmptyQuickEstimateStorage()`: 설정을 변경하지 않고 같은 대상과 보호·서식·입력 규칙·출처 표식을 읽어 검사한다. 준비 단계의 재검증용이며 업무 행이 생긴 뒤에는 의도적으로 실행을 거부한다.

기존 `Code.gs`는 편집기에서 전체 내용을 다시 읽어 로컬 생성물과 일치를 확인했고, 앞 절의 SHA-256을 유지했다. 준비 코드는 고객 행 추가·메일·트리거 설치·웹앱 배포를 수행하지 않는다.

보호는 파일 공유 권한과 별개이며 문서 소유자 자신의 편집을 차단하는 장치는 아니다. 현재 범위는 1,000행 grid 기준이다. 운영 중 grid를 확장한다면 보호·검증 범위 확장도 별도로 확인한다. 준비 함수를 업무 데이터가 생긴 시트에 재실행하여 확장하지 않는다.

### 검증 과정에서 확인한 차이

초기 사전 검사가 기존 v1 고지의 설명 문구 차이를 발견해 쓰기 전에 중단했다. 실제 새 시트의 `기존 v1 요청용 개인정보 고지 버전` 문구를 유지하도록 준비 검증 기준을 수정했다. 이어 Google의 담당자 custom formula readback이 B3 셀에서는 B3를 참조한다는 점과 날짜 유형이 `DATE_IS_VALID_DATE`임을 실제 응답으로 확인했다. 행별 상대 참조 비교와 Google 타입의 enum key 검사를 추가했다. 잘못된 참조나 입력 허용으로 검증을 느슨하게 만들지 않았다. 날짜 유형은 [Google 공식 기준](https://developers.google.com/apps-script/reference/spreadsheet/data-validation-criteria)과도 대조했다.

일반 E2E에서는 SPA unmount 직후 모의 응답이 완료되기 전에 fixture가 닫히는 오류를 재현했다. 기존 테스트의 검증 내용을 유지하고 끝에 `unrouteAll({ behavior: "wait" })`만 추가했다. 오류를 무시하는 방식은 사용하지 않았으며 해당 시나리오는 수정 후 3회 연속 통과했다.

### 후속 검증 상태

2026-10-23 15:57 KST에 준비 함수가 Google에서 정상 완료됐다. 보호·입력 검증·서식 readback 후 출처 migration도 성공하여 `QUICK_ESTIMATE_ATTRIBUTION_SCHEMA=2`가 됐다. 15:59 KST에는 설정을 바꾸지 않는 별도 `verifyEmptyQuickEstimateStorage()`도 동일한 결과로 완료됐다. 준비·재검증 모두 원본 0행, 상담 0행, codebook 40행, 보호 7개, 입력 검증 5종, 조건부 서식 4개를 확인했다. Google UI에서도 보호 7개와 출처 범위를 확인했다. 트리거 0개, 활성·보관 배포 모두 없음, 시트 나에게만 공개 상태를 재확인했다.
