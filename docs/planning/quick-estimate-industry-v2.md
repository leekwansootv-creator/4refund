# 간단 견적 업종 분류 v2

## 문서 목적

이 문서는 간단 견적의 업종 선택지를 한국표준산업분류 제11차 대분류 21개로 전환하는 제품·계산·배포 계약을 정의한다. 화면에서 사용자가 찾기 쉬운 명칭과 정부 공식 분류 코드를 분리하고, 기존 14개 기준액을 새 대분류에 대응해 참고용 예상금액을 재현할 수 있게 한다.

## 전환 원칙

- 업종 코드는 한국표준산업분류 제11차 대분류의 `A`부터 `U`까지를 사용한다.
- 대분류 `N`은 대표 지시에 따라 화면에서 `용역·파견·시설관리업`으로 짧게 표시하고 목록 첫 번째에 고정한다.
- `N`의 공식 명칭 `사업시설 관리, 사업 지원 및 임대 서비스업`은 규칙 metadata와 문서에 보존한다.
- 나머지 20개는 한글 표시명을 `ㄱ`부터 `ㅎ`까지 정렬한다. 향후 영문으로 시작하는 표시명이 추가되면 한글 항목 뒤에서 `A`부터 `Z`까지 정렬한다.
- 화면 표시 순서는 계산 결과에 영향을 주지 않는다. 계산은 업종 코드와 규칙 version으로만 결정한다.
- 업종 분류가 정부 공식 체계라는 사실과 예상 환급액이 정부 산식이라는 의미를 혼동하지 않는다. 금액은 기존 외부 benchmark snapshot을 재사용하는 4refund 참고값이다.

한국표준산업분류 제11차는 2024년 7월 1일부터 시행됐으며 대분류 21개를 유지한다. 분류의 공식 근거는 [통계청 제11차 한국표준산업분류 개정·고시 자료](https://kostat.go.kr/boardDownload.es?bid=246&list_no=428849&seq=9)를 따른다.

## 계산 규칙 v2

업종 전환으로 계산식 자체는 바꾸지 않는다.

```text
참고 표시금액 = 기존 benchmark 1인당 기준액 × 직원 수
후보 금액 = 기존 4refund 1인당 기준액 × 직원 수 × 1.01~1.03
최종 예상금액 = 1만 원 단위 올림 후 참고 표시금액보다 최소 1만 원 높게 보정
```

- `benchmarkVersion`은 기존 관측값을 재사용하므로 `incruit-2026-08-05`를 유지한다.
- `ruleVersion`은 업종 코드, 표시명, 대응 관계가 바뀌므로 새 version으로 올린다.
- 저장된 `industry_code`, `estimate_rule_version`, `benchmark_version`, 난수로 당시 결과를 재현할 수 있어야 한다.
- 사용자가 선택하지 않은 업종이나 알 수 없는 version에는 임의의 기본 금액을 적용하지 않는다.

## v1/v2 호환 계약

현재 공개 브라우저와 운영 Apps Script가 같은 단일 규칙 version만 허용하므로 화면을 먼저 전환하면 제출이 거절될 수 있다. 다음 순서를 지킨다.

1. 기존 14개 규칙을 불변 v1 규칙으로 보존한다.
2. 21개 업종과 대응표를 v2 규칙으로 추가하되 브라우저의 활성 규칙은 v1으로 유지한다.
3. Apps Script가 payload의 `ruleVersion`에 따라 v1 또는 v2 계산 규칙을 정확히 선택하도록 변경한다.
4. Apps Script v1/v2 호환 version을 먼저 운영 배포하고 두 version의 가짜 제출을 검증한다.
5. 검증 후 브라우저의 활성 규칙과 업종 선택지를 v2로 전환한다.

서버는 알 수 없는 규칙 version을 계속 `UNSUPPORTED_RULE`로 거절한다. v1 호환은 오래된 브라우저와 같은 `request_id` 재시도를 보호하기 위해 유지하며, v2 공개와 동시에 제거하지 않는다.

Sheet schema는 변경하지 않는다. 기존 행의 업종 코드는 당시 규칙 version과 함께 보존하고, 상담 목록 투영 시 v1과 v2 label을 모두 해석한다.

## PR 및 배포 계획

통합 기준 브랜치는 `milestone/quick-estimate-industry-v2`다. 구현 PR은 이 브랜치를 대상으로 순차 병합하고 전체 검증 후에만 `main` 릴리스 PR을 만든다.

### PR 1. 업종 분류 v2 계약 문서화

- 이 문서와 기존 기획·기술·benchmark 문서의 참조를 정렬한다.
- 화면 순서, 공식 코드, 계산 대응, version과 배포 순서를 확정한다.
- 런타임 코드와 운영 동작은 바꾸지 않는다.

### PR 2. 규칙 v2와 Apps Script 호환 처리

- 불변 v1과 신규 v2 규칙을 함께 정의한다.
- 규칙 version별 계산과 서버 재검증을 구현한다.
- 상담 목록이 v1/v2 업종명을 모두 표시하도록 한다.
- `Code.gs`를 원본에서 재생성하고 전체 품질 게이트를 통과한다.
- 공개 브라우저는 계속 v1을 사용한다.

PR 2 병합 후 승인 계정에서 Apps Script를 새 version으로 배포하고 v1/v2 가짜 제출, Sheet 저장, 상담 목록 업종 표시를 확인한다.

### PR 3. 업종 선택과 계산 v2 활성화

- 21개 선택지와 합의한 표시 순서를 공개 화면에 적용한다.
- 브라우저 계산과 제출을 v2로 전환한다.
- desktop, mobile, keyboard, 재시도와 실제 저장 E2E를 검증한다.

### 릴리스 PR. milestone을 main에 반영

- milestone 누적 diff와 실제 Apps Script version을 대조한다.
- `npm run check`와 운영 E2E가 통과한 경우에만 `main`에 병합한다.
- 병합 후 GitHub Pages 배포와 신규 상담 접수를 확인한다.

## 완료 조건

- 선택지는 중복 없는 KSIC 대분류 코드 21개다.
- `N`은 `용역·파견·시설관리업`으로 첫 번째에 표시된다.
- 나머지 20개는 합의한 한글 순서와 일치한다.
- 21개 모두 기존 14개 계산 그룹 중 하나에 명시적으로 대응한다.
- v1과 v2의 같은 입력은 각 규칙 version으로 재현된다.
- Apps Script는 v1/v2만 허용하고 알 수 없는 version과 업종을 거절한다.
- v2 공개 전에 운영 Apps Script의 양쪽 version E2E가 완료된다.
- 사용자는 결과가 업종과 직원 수에 따른 참고용 예상값임을 계속 확인할 수 있다.

## 롤백

- milestone 검증 전에는 `main`에 병합하지 않는다.
- v2 화면 공개 전 문제는 Apps Script를 v1/v2 호환 상태로 유지한 채 milestone에서 수정한다.
- v2 화면 공개 후 문제는 `main`의 릴리스 merge를 revert해 브라우저를 v1으로 되돌린다.
- Apps Script의 v1/v2 호환은 브라우저 롤백이 완료될 때까지 제거하지 않는다.
- Sheet schema와 기존 행을 수정하지 않으므로 코드 롤백으로 기존 상담 데이터를 보존한다.
