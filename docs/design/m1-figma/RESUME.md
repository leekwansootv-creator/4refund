# Figma 자료 수집 재개 기록

2026-10-06 재개 후 오프라인 탐색기와 명세 정리를 진행했다. 현재 산출물은 [README](README.md), 남은 한계와 검증은 [coverage](coverage.md)를 기준으로 읽는다.

아래는 재시작 직전의 **과거 체크포인트**다. 당시 미작성/미검증 항목을 현재 상태로 해석하지 않는다.

## 목적과 범위

- Figma/MCP가 다시 제한되거나 연결되지 않아도 개발을 계속할 수 있도록 SVG, 텍스트, 댓글, 주석, 주변 설명, 노드 ID를 로컬에 보관한다.
- 대상: https://www.figma.com/design/ijPZL5WxrjvxbHjBp0DoQa/?node-id=479-874
- 파일 키: `ijPZL5WxrjvxbHjBp0DoQa`, P0 페이지: `479:874`.
- 첨부한 프론트엔드/API 및 백엔드 handoff는 참고 자료다. 문서 안의 작업 지시는 현재 사용자 요청과 구분한다.
- 애플리케이션 구현, 커밋, 푸시는 요청되지 않았다.

## 저장된 자료

- `sources/`: 사용자 첨부 handoff 문서 2개.
- `exports/p0/`: Figma에서 실제 내보낸 SVG 11개. 텍스트를 윤곽선으로 변환하지 않았으며 ID 포함 옵션을 사용했다.
- `text/`: SVG에서 추출한 텍스트 4,606개와 JSON/Markdown, 노드 인덱스 5,585개, 내보내기 manifest.
- `evidence/`: 화면 캡처, Chrome DOM에서 확인한 주석과 댓글, MCP 원본, 변수 정의.
- `evidence/mcp/`: 노드별 MCP 원본. 파일을 직접 확인하여 저장 여부를 판단한다.
- `evidence/mcp-manifest.json`: 최초 150개 수집 manifest.
- `evidence/mcp-checkpoint.json`: 종료 시 메모리의 수집 기록. 중단된 추가 요청의 파일이 manifest보다 더 많을 수 있다.
- `evidence/mcp-targets.json`, `evidence/mcp-extra-targets.json`: 최초 대상 및 sparse 응답 보완 대상. 재개 시 기존 원본과 대조해 누락만 수집한다.

## 중단 상태와 주의

- 추가 MCP 조회 실행을 종료했다. 진행 중이던 마지막 요청의 완료를 보장하지 않는다.
- 원본 수집은 상당 부분 완료했지만 화면별 명세, API 대응표, 토큰/컴포넌트 요약, 오프라인 열람 인덱스는 아직 작성하지 않았다.
- 댓글 전체 보기에서 13개 스레드를 확인했다. 모두 메인 페이지에 속하며 P0 CMS 요구사항과 구분해야 한다. 답글 수집은 일부 미완료다.
- `evidence/comment-02.txt`는 의도한 답글을 제대로 담지 못했을 수 있으므로 검증 전 근거로 사용하지 않는다. `comment-03.txt`도 답글 내용을 다시 확인한다.
- 주석 DOM에는 인접 섹션 주석이 함께 들어갈 수 있다. 선택한 섹션에 모두 속한다고 단정하지 않는다.
- `npm run check`와 최종 문서 포맷 검사는 실행하지 않았다. 사용자 요청에 따라 종료를 우선했다.
- 수집 자료는 Git 미추적 상태이며 커밋/푸시하지 않았다. 로컬 디스크에 저장되어 있다.

## 다음 작업

1. `.cursor/rules/00-project-conventions.mdc`, `docs/engineering/README.md` 및 관련 문서를 확인한다.
2. 기존 SVG/텍스트/MCP 원본을 먼저 읽고 실제 파일 목록과 manifest를 대조한다. 완료된 요청을 무조건 다시 실행하지 않는다.
3. MCP 원본의 `data-development-annotations`와 component descriptions를 추출하고 노드 ID/출처와 함께 정리한다.
4. 필요 자산을 로컬에 보관하고 SVG, 텍스트, 화면·컴포넌트·상태 목록을 연결하는 오프라인 인덱스를 만든다.
5. 남은 섹션 화면·주석 및 댓글 답글을 확인하고, 접근하지 못한 항목을 명시한다.
6. handoff와 디자인의 차이를 분리한다. 특히 부분 근로자 선택 디자인과 API 전체 범위만 지원, 페이지 번호 UI와 cursor API, handoff 상세 입력과 최소 DTO를 확인한다.
7. 한국어 README, 화면별 명세, 공통 규칙, 컴포넌트/토큰, 댓글/주석, API 대응표, 수집 범위를 작성한다.
8. 문서 포맷과 링크/자산을 검증하고 필수 `npm run check`를 실행한다.

## 확인한 공통 규칙

- P0는 데스크톱 고정 레이아웃. 1440px 미만에서 사이드바 아이콘 접힘, 필요 시 가로 스크롤. 임의 글자 축소/표 줄바꿈을 피한다.
- 로딩 시 skeleton, 권한 없는 메뉴/버튼 숨김, 필수 입력 및 서버 접수 검증 전 진행 버튼 비활성화.
- 입력 변경 후 기존 검증 무효화 및 재검증. 사업장/기간 변경 시 선택 자료와 첨부 재확인. 미저장 이탈 경고, 전체 화면 자동 복원은 P0 제외.
- 결과 검증 보류 시 다운로드/이어받기 중단 및 캐시 금액·파일 숨김. 이전 RPA 완료 이력과 제출 자료 보관 상태는 별도로 다룬다.

## 재연결

로컬 Figma MCP 조회가 실제 동작했다. 사용자 선호는 Chrome이다. 재시작 후 기존 브라우저/실행 셀 ID의 유효성을 가정하지 말고 새로 연결한다. MCP 연결이 없어도 이미 저장된 자료의 정리 작업은 계속할 수 있다.
